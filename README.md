# Synapse
### RAG-Powered Intelligent Study Assistant

Synapse is a production-grade study assistant built on Retrieval-Augmented Generation. Students upload their lecture notes, slides, and past exam papers. The system indexes this material and enables grounded Q&A and quiz generation based exclusively on the uploaded content.

---

## Architecture

The system runs as a single FastAPI service with two pipelines:

**Ingestion Pipeline** (triggered on file upload)
```
Uploaded file
    Parser (PDF / PPTX / DOCX)
    Chunker (semantic for prose, structural for slides)
    Embedder (SentenceTransformerEmbeddingFunction)
    ChromaDB (PersistentClient, cosine similarity)
```

**Query Pipeline** (triggered on student interaction)
```
Student message
    ChromaDB similarity search
    Similarity threshold check (0.45)
    If covered: Groq LLM generates grounded answer
    If not covered: returns explicit "not covered" response
```

---

## Data Flow

```
POST /uploadfiles/
    UploadFile (bytes) -> tempfile (disk path) -> Parser -> Chunker -> Embedder -> ChromaDB
    tempfile deleted after parsing (process-and-discard)

POST /chat/
    message -> ChromaDB query_texts -> threshold check -> Groq llama-3.1-8b-instant -> response
    LangSmith traces every LLM call

POST /quiz/
    topic + format + num_questions -> ChromaDB retrieval -> Groq -> JSON question list
    Supports MCQ, True/False, Short/Long formats
```

## Tech Stack

| Layer | Choice | Reason |
|---|---|---|
| Backend | FastAPI (async) | Production-grade, auto-generates API docs |
| Vector store | ChromaDB embedded | Free, persistent, cosine similarity via metadata |
| Embeddings | sentence-transformers all-MiniLM-L6-v2 | Local inference, no API cost |
| LLM | Groq llama-3.1-8b-instant | Free tier, fast inference |
| PDF parsing | LangChain PyPDFLoader | Page-level extraction with metadata |
| PPTX parsing | python-pptx | Direct slide-level control (LangChain loaders lose slide boundaries) |
| DOCX parsing | LangChain Docx2txtLoader | Clean continuous text extraction |
| Observability | LangSmith (@traceable) | Full trace per LLM call without LangChain wrappers |
| Evaluation | RAGAS | Faithfulness, context precision, context recall, answer relevancy |

## Chunking Strategy

Document type determines chunking strategy:

- **PDF / DOCX** -- semantic chunking (LangChain SemanticChunker with percentile breakpoints). Text is concatenated across pages with [PAGE N] markers before chunking so topic continuity is preserved across page boundaries.
- **PPTX** -- structural chunking (one slide = one chunk). Slides are marked with [SLIDE N] markers and split by regex. Semantic chunking is not appropriate for slides because individual slides are already discrete semantic units.
- **PYQ (past exam papers)** -- reuses PDFParser with file_type='pyq'. No separate parser needed; the file_type label routes PYQ content to appropriate retrieval tools.

---

## Grounding Rules

Chat/Study mode enforces strict grounding:

- If retrieval returns chunks with cosine distance below 0.45 (topic present): RAG context is injected, LLM may elaborate beyond the notes
- If all retrieved chunks score above threshold (topic absent): returns "This topic is not covered in your uploaded material" without calling the LLM

Quiz mode uses loose grounding: notes provide topic context, LLM generates exam-style questions that may go beyond the literal text.

Known limitation: short queries (e.g. "BST") fail retrieval due to vocabulary mismatch between query and document embeddings. Planned fix: hybrid search (BM25 + vector) in v1.2.

## Key Engineering Decisions

**Process-and-discard for uploaded files.** Raw files are written to a tempfile, parsed, then deleted immediately. Only chunks and embeddings persist in ChromaDB. Eliminates need for object storage.

**ChromaDB native embedding function.** Using SentenceTransformerEmbeddingFunction (not LangChain's HuggingFaceEmbeddings) ensures storage and query use identical embedding space. Earlier attempt with manual embed_documents() caused L2 vs cosine distance mismatch producing incorrect similarity scores.

**Similarity threshold as environment variable.** SIMILARITY_THRESHOLD defaults to 0.45, configurable per environment without code changes.

**LangSmith via @traceable decorator.** Direct Groq SDK calls (not LangChain wrappers) are traced using the @traceable decorator, capturing inputs, outputs, and latency per function without switching LLM providers.

## Running Locally

```bash
git clone https://github.com/venkatesh-akhouri/Synapse-RAG-based-Exam-Prep-Platform
cd Synapse-RAG-based-Exam-Prep-Platform

uv pip install -r pyproject.toml

# Create .env with:
# GROQ_API_KEY=
# LANGSMITH_API_KEY=
# LANGSMITH_TRACING=true
# LANGSMITH_ENDPOINT=https://api.smith.langchain.com
# LANGSMITH_PROJECT=Synapse
# SIMILARITY_THRESHOLD=0.45

uv run uvicorn main:app --reload
```
